def python_to_c(codigo_python):
    arvore = ast.parse(codigo_python)
    codigo_c = ""
    for no in arvore.body:
        if isinstance(no, ast.Print):
            # Traduz print() para printf()
            args = [ast.unparse(arg) for arg in no.args]
            codigo_c += f'printf("{args[0]}\\n");\n'

            alvo = ast.unparse(no.targets[0])
            valor = ast.unparse(no.value)
            codigo_c += f'int {alvo} = {valor};\n'
    return codigo_c

Por que getevent é "suja"?
1. Você está lendo o fluxo bruto do kernel
O /dev/input/eventX é um dispositivo cru, que entrega todos os eventos de toque, tecla, movimento, aceleração, etc., sem nenhum tratamento.

Você recebe milhares de eventos por segundo, incluindo:

Toques na tela.

Teclas virtuais.

Movimento do dedo.

Pressão, orientação, etc.

Resultado: Seu programa precisa filtrar o que é relevante (ex: só teclas numéricas) e ignorar o resto. Isso é trabalhoso e sujeito a erros.

2. Você precisa mapear coordenadas para caracteres
O getevent entrega coordenadas X/Y do toque, não o caractere digitado.

Para saber qual tecla foi pressionada, você precisa:

Saber o layout do teclado (QWERTY, AZERTY, numérico, etc.).
Saber o tamanho e posição de cada tecla na tela.
Mapear as coordenadas para a tecla correspondente.
Exemplo:

Toque em (x=150, y=300) → No teclado numérico, isso pode ser o número 5.

Mas se o teclado for redimensionado ou o usuário trocar de idioma, seu mapeamento quebra.

3. Você não tem contexto da interface
O getevent não sabe se o toque foi em um campo de senha, em um botão ou em uma imagem.

Você captura todos os toques, inclusive:

Toques em anúncios.

Toques em menus.

Toques em notificações.

Isso gera muito ruído (dados inúteis) que você precisa filtrar.

4. Você perde eventos se não ler rápido o suficiente
O buffer do kernel é limitado (ex: 100 eventos).

Se seu programa demorar para ler, o buffer transborda e você perde eventos.

Em Python (interpretado), isso é muito comum – daí a recomendação de usar C.

5. Você não tem acesso a campos ofuscados
Apps de banco/carteira usam teclados próprios que desenham os números como imagens, não como textos.

O getevent só vê coordenadas, não vê o número que aparece na tela.

Você precisa reconstruir o número a partir das coordenadas – o que é quase impossível se o teclado for embaralhado a cada toque (como alguns apps fazem).

Por que getevent ainda é eficaz?
Mesmo com todas as desvantagens, getevent é usado porque:

Funciona em qualquer Android (não precisa de Root se você tiver permissão de acessibilidade? Não, precisa de Root para ler /dev/input).

É simples de implementar (um loop que lê eventos).

É rápido (em C, lê milhares de eventos por segundo sem perder).

Captura TUDO – você não depende de hooks ou injeção em processos específicos.

// Script Frida para capturar hash MD5 gerado pelo sistema
Java.perform(function() {
    var MessageDigest = Java.use("java.security.MessageDigest");
    MessageDigest.digest.overload('[B').implementation = function(bytes) {
        var hash = this.digest(bytes);
        console.log("Hash capturado: " + bytesToHex(hash));
        return hash;
    };
});

function bytesToHex(bytes) {
    var hex = '';
    for (var i = 0; i < bytes.length; i++) {
        hex += ('0' + (bytes[i] & 0xFF).toString(16)).slice(-2);
    }
    return hex;
}
